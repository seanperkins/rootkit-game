# Follow-up measurements — 2026-09-05

See [the implementation record](../../progression-bosses-music.md) for interpretation and limitations.

- `coverage-final.jsonl`: eighteen seed-42 first-boss cases (fresh/moderate/full × solo/four × breadth/rank/corruption). Includes checkpoints and all terminal outcomes. `linear-solo.jsonl` repeats the three fresh-solo cases with only the late XP surcharge removed.
- `progression_survey.gd.txt`: instrument used for both. Copy to `tools/progression_survey.gd` in an isolated checkout and run `godot --headless -s res://tools/progression_survey.gd -- label=coverage-final seeds=42 limit=21000`. For the matched linear check, remove `+ (late * late + 1) / 2` from the XP cost and add `profiles=fresh parties=1 label=linear-check`. These are real-input bot observations, not full campaign or human playtests.
- `cross-architecture.txt`: `tools/determinism_cross_arch.sh 1800`, Godot 4.7 / Ubuntu 24.04. Identical arm64/x86_64 hashes for this finite workload.
- `relay.txt`, `punch.txt`, `punch-trace.txt`, `relay-after-punch-timeout.txt`: existing live relay/punch probes and temporary diagnostic variants. All clients ran on one Mac through the internet relay. Candidate exchange occurred, direct handshakes failed, relayed records still arrived after timeout. The `.gd.txt` variants can be copied into `tools/` to rerun. These probes contact the configured relay; they do not deploy anything.
- `presentation-original.txt`, `presentation-final.txt`: actual windowed four-player mixer audits before/after changing the chase separation threshold from 15 to 210. `presentation_audit.gd.txt` records Master/Music WAVs under `.tmp/` and counts beat masks; copy into `tools/` and run windowed. It uses a dedicated temporary save. Voice order is chase, charger, flanker, support, ambusher, ranged, then player slots 0–3. Counts cover only beats with at least 100 enemies.
- `chase-threshold-coarse.txt`, `chase-threshold-fine.txt`, `threshold_audit.gd.txt`: simultaneous candidate crossing measurements. Coarse candidates were 15/30/60/120/240/480; archived fine source uses 15/120/150/180/210/240. Its extra force observers make it unsuitable as a performance benchmark. Recordings and sample counts establish cadence/headroom, not listening quality.
- `mixer-metrics.json`: duration, peak, RMS and count of samples at or above 0.99 full scale, measured from 16-bit PCM recordings. Local WAVs remain in `.tmp/busy[-final]-{master,music}.wav` and are not shipping assets.
- `circuits-windowed.txt`: all three runtime subnet screenshots after irregular circuit placement. Local previews: `.tmp/world-subnet-{1,2,3}.png`; matched earlier layouts: `.tmp/circuits-before-{1,2,3}.png`. Reproduce final previews with `godot -s res://tools/shot_world_visuals.gd`.
- `focused-tests.txt`: three affected suites after the final circuit/cadence edits. `performance.txt` records the subsequent serial performance gate with unchanged timing budget and workload pin.

Presentation and screenshot logs retain their two-instance ObjectDB cleanup warnings. The full 66-suite integration run and successful earned-upgrade campaign are archived in the sibling `2026-09-05` folder. Temporary scripts are kept as text to avoid expanding the normal test runner; restore them only when reproducing these experiments.
