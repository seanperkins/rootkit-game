# Weapons/trigger rework implementation plan

Date: 2026-09-04. Status: implemented and windowed-smoke verified; affected suites plus perf are the per-feature gate. Full-suite verification is deferred until the remaining features are integrated, per the user's updated workflow.

Spec: [Weapons and triggers](../specs/2026-09-04-weapons-trigger-rework-design.md).

## Ownership and prerequisites

Main integration owner serializes shared `run.gd`/`ui.gd` edits against music, terrain and boss work. A writing worker may own pure build/data changes, but publishes the complete stat/placement contract before UI consumes it. No concurrent formatter/build/test runs during writes. LSP is available: refresh references before exported-symbol changes and use its refactors where supported. Exclude other worktrees from migration.

The user's approval fixes bounce at 1.4 damage / 150 radius / 1.5 s and bare cadence at 1.5. **`cooling` → sheet `clock_speed`; `overclock` / `race_condition` → own fast shield, no new stat** (see spec). The later self-contained-shield choice supersedes the unreachable recovery-only prototype.

## Implementation sequence

1. **Implement the approved non-firing stat contract.** Move `cooling` to `SHEET_EFFECT` `clock_speed`; remove `haste`→cooldown from `Compiler.MULT_KEYS` and the multiplier namespace. Replace payload cadence with each payload's own `shield` and unranked `shield_rearm`; preserve existing MAX folding. Keep saved ranks and identical derivation on every peer.
2. **Cut over build and placement behavior.** Change `Loadout.start(packet, interval)` to `start(packet)`; migrate active runtime and test fixtures. Update `Compiler.BARE_CADENCE` and preserve vector cooldown's existing unranked carve-out. Make legal manual placement, auto placement and fusion all enforce a prospective unconditional-firing census, including bare rows and fused intervals. Retarget the approved non-trigger cadence paths and migrate affected recipes without aliases or dead stat keys. Update bounce in `ModuleTable`. Do not add a per-bounce compiler exception.
3. **Implement truthful upgrade/shop presentation.** In `scripts/run/ui.gd`, extend existing card selection/row highlighting to show compiled before/after values without mutating live state. Reuse build/placement logic; no UI-side formula copies. Revise `meta_screen.BUFFS` cooling wording and runtime comments that claim shop cooling controls fire rate. Verify recovery timing at `_emit_vector`/`_shield_left` if recovery is selected. Preserve staging through `choose_card`; controller and keyboard navigate the same selection model.
4. **Migrate broken contract coverage and exercise the feature.** Relevant existing suites: `test_build`, `test_slots`, `test_fusion`, `test_fusion_run`, `test_meta_derivation`, `test_meta`, `test_player_stats`, `test_multipliers`, `test_cadence`, `test_triggers`, `test_facing`, `test_cards_keyboard`, `test_hud`. Keep tests of actual guarantees; remove purely incidental assertions rather than re-pin them. In particular, replace haste-driven cooldown-floor fixtures with real trigger-driven floor cases; remove redundant haste parameter sweeps. Add permanent coverage only for plausible bugs such as the first bare-row event-trigger deadlock or a preview that mutates live state. Use a disposable actual-run driver for the remaining numerical examples and state hashes. Run `tools/run_tests.sh` once after all source/test edits settle, with real UDP available; never trust a suite run directly. The runner does not support per-suite selection. Inspect BROKEN/FAIL/INCONCLUSIVE outcomes, not only process exit.
5. **Inspect surfaces and finish documentation.** Launch Godot windowed with test saves and check starter firing, legal/blocked trigger choices, row previews, replacement losses, cooling text and bounce knockback. Exercise keyboard/controller paths, not just screenshots. Record exact measured periods, hit counts and preview/apply agreement. Re-measure the existing performance gate's load and explain any required coverage re-pin; do not change its time budget to fit the feature. After successful smoke, remove disposable drivers and their sidecars, update maintained README/manual/source rationale and the approved status; generated codemaps must be regenerated by the established process, never hand-edited. No implementation commit/push is implied by this plan.

## Verification scenarios

| Scenario | Observable requirement |
|---|---|
| New run, no cards | A packet emits every 0.75 s at baseline; no trigger module is present. |
| First card is on_hit/on_kill | Cannot replace the sole unconditional source; another genuinely firing bare row permits the placement. |
| Fusion consumes final interval | Refused if result leaves no unconditional source; fused interval is itself sufficient. |
| Bounce interval versus bare | 1.50 s versus 2.25 s emission periods, base radius 150 and damage 1.4; vector rank changes damage/radius but not base cadence. |
| Preview and actual pick | Actual resolved values match preview after INPUT is consumed; preview itself changes no hash or RNG. |

Also exercise fresh and maxed shop profiles, a shield with/without positive rearm if applicable, absent/dead slot builds, and identical snapshots across peers. Fixture assertions that intentionally need a pre-equipped interval must place it explicitly after `start(packet)`; do not weaken their substantive contract to match a new starter.

## Implementation evidence

- Windowed Godot smoke passed: fresh packets emit four times in three seconds;
  interval preview changes 0.75 s to 0.50 s; a staged card produces the previewed
  resolved build without preview changing the simulation hash.
- Bare bounce emits twice within one simulation tick of 4.5 s. Its rendered
  pulse and the selected-build comparison were inspected at 1280×720.
- Both replacement payloads grant their own pool, refuse early refills, and
  refill on an emission after rearm. Cooling rank 10 gives 280 movement speed
  while the starter period remains 0.75 s. The actual upgrades page reads
  “move speed +6 per rank.”
- Coverage measured DIED 23727, mean enemies 208.2, hits/tick 1.40,
  kills/tick 0.266. The gate records the reason for re-pinning these workload
  figures; its timing budget and tolerance bands are unchanged. This is not
  evidence that normal-player campaign balance improved.
- Disposable smoke driver removed after passing. README, manual generator and
  the unconditional-firing invariant are updated. Regenerated `build.md`,
  `data.md`, `ui.md` and the architecture overview using the installed
  `cc-codemaps` skill directly from its Claude plugin path. Current source
  and generated diffs were checked; no global skill configuration changed.
- Final focused runner: **14 suites passed, no script errors** — build, slots,
  cadence, fusion, multipliers, meta, player stats, meta derivation, card
  keyboard, facing, parking, offers, manifest and perf. Real-run p95 was
  **9.426 ms**, within the **10.340 ms** scaled budget. The in-flight full run
  was cancelled at the user's request; a full-suite pass is not claimed.
- Replaced the obsolete two-factor payload/trigger fixture with a legal
  trigger-period regression that also catches a zero-initialized cadence
  accumulator. `test_build` and `test_cadence` passed after this test-only edit.
