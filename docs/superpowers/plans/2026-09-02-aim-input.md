# Aim Input Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a right stick or a recently moved mouse set the player's facing through the lockstep record, and draw the player as an arrow along that facing.

**Architecture:** The input record gains an `aim` vector carried by `Protocol`, `Transport` and `Lockstep` beside `move`, as a TRAILING argument with a zero default so every existing caller keeps compiling. The run applies it into `aims[slot]` through `_sanitise_aim`, and `_step2_integrate` lets a non-zero aim set `player_facing` ahead of movement. The device is sampled only in `_poll_local_input`; mouse recency is a countdown decremented in `_process`, so no clock is read. The player disc becomes an arrow.

**Tech Stack:** Godot 4.7, GDScript. Suites are `SceneTree` scripts run with `godot --headless -s res://tests/<suite>.gd`; the runner is `tools/run_tests.sh` (the loopback suite needs the Bash sandbox off).

**Spec:** `docs/superpowers/specs/2026-09-02-aim-input-design.md` — read it first. One deviation from its signatures, chosen here: `aim` is the LAST parameter of `submit`, `take`, `encode_input`, `send_input` and `_accept_record`, with a default, rather than inserted after `move`. Twenty-odd suite call sites keep compiling and the wire format is what the spec says.

## Global Constraints

- `test_determinism_rules`: no `Time.get_`, `Engine.time_scale`, `Input.` in any `_step*` function, `_apply_records`, `_physics_process` or the other listed sim functions; `Input.` appears in exactly one function of `run.gd`, `_poll_local_input`. `test_input` enforces the same one-place rule.
- Every `var` in `run.gd` is in `STATE_FIELDS` or `NOT_IN_MANIFEST` (`test_manifest`). New simulation state: `aims` (beside `inputs`, `SH`). New non-simulation: `_rec_aims` (take buffer), `aim_override` (test seam), `_mouse_iso`, `_mouse_aim_left` (local presentation).
- `SessionRules.PROTOCOL` goes 1 → 2; `Protocol.INPUT_BODY` 20 → 28; `Protocol.RELAY_RECORD` 25 → 33.
- `MOVE_COMPONENT_MAX` (1.3635) bounds an aim component exactly as it bounds a move component; a non-zero sanitised aim is normalised.
- No image assets, no font files, no `Area2D`.
- Run suites through `tools/run_tests.sh` at the end. Commit after every task, on branch `aim-input` off `main`.
