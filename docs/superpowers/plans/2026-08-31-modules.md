# New Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Ten vectors, three triggers and four payloads — and the runtime mechanics they need.

**Architecture:** Five new stat keys become fields on `ResolvedExploit` with explicit fold rules. Four new `VectorKind`s each get one branch in `_emit_vector`; the other six vectors are stat and tag variants of existing kinds. Three new `TriggerKind`s hook events that already exist.

**Spec:** `docs/superpowers/specs/2026-08-31-modules-design.md`

## Global Constraints

- Run tests with `tools/run_tests.sh`. The runner fails on any `SCRIPT ERROR`; a bare `PASS` is not evidence.
- Every test case marks itself finished on its last line.
- `Module.STAT_KEYS` is a closed set and every key is a field on `ResolvedExploit`. Adding a key without the field makes `_fold` write to nothing.
- **Enemy slow already exists** — `run.apply_slow`, `_slow_left`, `_slow_factor`, built for terrain's SLOW zones. The modules pass reuses it rather than adding a second implementation. The spec claims this mechanic as new; it is not, and one mechanic with one home is worth more than two that drift.
- Defensive magnitudes fold by MAX, offensive ones by sum. The argument is in `Compiler.MAX_FOLD_KEYS`: the same module is legal in many slots, and summing a defensive magnitude buys it at no uptime cost.
- Perf gate stood at p95 4.642 ms against a 10.198 ms budget.
- No AI attribution in commit messages.

### Task 1: Five stat keys, their fields, and their fold rules

**Files:** `scripts/build/module.gd`, `scripts/build/resolved_exploit.gd`, `scripts/build/compiler.gd`, `tests/test_build.gd`

- [ ] **Step 1: Write the failing test** — in `tests/test_build.gd`, assert that the three defensive keys fold by MAX across slots while `knockback` and `orbit_count` sum, and that `orbit_count` floors once at the end like `pierce` does.

```gdscript
func new_keys_fold_by_their_rule() -> void:
	var a := Module.make(&"k_a", "a", Module.Slot.PAYLOAD,
		{&"knockback": 40.0, &"shield": 10.0, &"orbit_count": 0.5})
	var b := Module.make(&"k_b", "b", Module.Slot.TRIGGER,
		{&"knockback": 30.0, &"shield": 25.0, &"orbit_count": 0.5})
	var ex := Exploit.new()
	ex.place(T[&"broadcast"]); ex.place(a); ex.place(b)
	var r := Compiler.build(ex)
	_check("knockback sums", r.knockback, 70.0)
	# Defensive: MAX, not sum. The same module is legal in many slots, and
	# summing a defensive magnitude buys it at no uptime cost.
	_check("shield takes the max", r.shield, 25.0)
	# Floored ONCE at the end, like pierce: 0.5 + 0.5 must be 1, not 0 + 0.
	_check("orbit_count sums then floors once", r.orbit_count, 1)

	var s1 := Module.make(&"s_1", "s1", Module.Slot.PAYLOAD,
		{&"slow_amount": 0.5, &"slow_duration": 1.0}, [&"slow"])
	var s2 := Module.make(&"s_2", "s2", Module.Slot.TRIGGER,
		{&"slow_amount": 0.3, &"slow_duration": 3.0}, [&"slow"])
	var ex2 := Exploit.new()
	ex2.place(T[&"broadcast"]); ex2.place(s1); ex2.place(s2)
	var r2 := Compiler.build(ex2)
	_check("slow_amount takes the max", r2.slow_amount, 0.5)
	_check("slow_duration takes the max", r2.slow_duration, 3.0)

	# The tag rule, mirroring the corruption one: stat and tag must not drift,
	# because the runtime gates on the tag while the amount comes from the stat.
	var untagged := Module.make(&"s_bad", "bad", Module.Slot.PAYLOAD,
		{&"slow_amount": 0.5})
	_check("slow without its tag is rejected",
		Compiler.validate(untagged).size() > 0, true)
	finished["new_keys_fold_by_their_rule"] = true
```

- [ ] **Step 2: Run to verify it fails.**

- [ ] **Step 3: Implement** — add the five keys to `STAT_KEYS`, the five fields to `ResolvedExploit` (with `orbit_count` untyped like `pierce`, so it accumulates as float and floors once), add `slow_amount` / `slow_duration` / `shield` to `MAX_FOLD_KEYS`, floor `orbit_count` alongside `pierce` in `build`, and add the tag rule to `validate`.

- [ ] **Step 4: Verify.** **Step 5: Commit** — `feat: five new stat keys with explicit fold rules`

### Task 2: Knockback and the player shield

**Files:** `scripts/run/run.gd`, `tests/test_effects.gd` (create)

**Interfaces:** `run._knock: PackedVector2Array`, `run.apply_knockback(i, impulse)`, `run.player_shield: float`, `KNOCK_DECAY`.

- [ ] **Step 1: Write the failing test**

```gdscript
func knockback_pushes_then_fades() -> void:
	var r := await _fresh_run()
	var i: int = r.enemies.spawn(Vector2(300, 0), Vector2.ZERO, 100.0, 12.0, 0)
	r._spawn_enemy_state(i, 100.0)
	r.apply_knockback(i, Vector2(400, 0))
	_check("an impulse is stored", r._knock[i].x > 0.0, true)
	var before: Vector2 = r.enemies.pos[i]
	r._step2_integrate(1.0 / 60.0)
	_check("and moves it outward", r.enemies.pos[i].x > before.x, true)
	for k in 120:
		r._step2_integrate(1.0 / 60.0)
	_check("the impulse decays away", r._knock[i].length() < 1.0, true)
	# A recycled slot must not inherit a live impulse.
	r._spawn_enemy_state(i, 100.0)
	_check("spawning clears it", r._knock[i], Vector2.ZERO)
	r.free()
	finished["knockback_pushes_then_fades"] = true

func the_shield_absorbs_before_integrity() -> void:
	var r := await _fresh_run()
	r.player_shield = 20.0
	var hp: float = r.player_health
	r.player_iframe = 0.0
	r._damage_player(8.0)
	_check("integrity is untouched while shielded", r.player_health, hp)
	_check("and the shield paid for it", r.player_shield < 20.0, true)

	# Overflow spills through to integrity rather than being swallowed.
	r.player_shield = 3.0
	r.player_iframe = 0.0
	r._damage_player(20.0)
	_check("a shield smaller than the hit spills over", r.player_health < hp, true)
	_check("and is spent", r.player_shield, 0.0)

	# It is NOT integrity: it does not heal and it does not show in the ratio.
	r.player_shield = 0.0
	r.player_iframe = 0.0
	var hp2: float = r.player_health
	r._damage_player(5.0)
	_check("with no shield the hit lands in full", r.player_health < hp2, true)
	r.free()
	finished["the_shield_absorbs_before_integrity"] = true
```

- [ ] **Step 3: Implement** — a `_knock` impulse array added to velocity in the integrate step and decayed exponentially; `player_shield` consumed at the top of `_damage_player` before mitigation reaches integrity. Clear `_knock` in `_spawn_enemy_state`.

### Task 4: Three new triggers

**Files:** `scripts/build/module.gd`, `scripts/run/run.gd`, `tests/test_triggers.gd`

- [ ] **Step 1: Write the failing test** — each fires on its event; `on_low_integrity` fires **once per crossing**, not once per tick under the threshold.

```gdscript
func low_integrity_fires_once_per_crossing() -> void:
	var r := await _fresh_run()
	# ... exploit with an ON_LOW_INTEGRITY trigger ...
	r.player_health = r._eff_integrity() * 0.9
	r._damage_player(r._eff_integrity() * 0.6)     # crosses below 40%
	var fires: int = r._trigger_fires.get(0, 0)
	_check("it fires on the crossing", fires > 0, true)
	for k in 60:
		r._step5_fire(1.0 / 60.0)
	_check("but not every tick spent under it",
		r._trigger_fires.get(0, 0), fires)
	# Rearms only after climbing back above.
	r.player_health = r._eff_integrity()
	r._damage_player(r._eff_integrity() * 0.7)
	_check("and rearms after recovering",
		r._trigger_fires.get(0, 0) > fires, true)
	finished["low_integrity_fires_once_per_crossing"] = true
```

- [ ] **Step 2: Run to verify it fails.**

- [ ] **Step 3: Implement** — add `ON_LOW_INTEGRITY, ON_FLIP, ON_LEVEL_UP` to `TriggerKind` after the existing four. Hook each where the event already happens: `_damage_player`, `_on_flip`, `_gain_xp`. `on_low_integrity` needs a `_low_armed` flag cleared on firing and set again when integrity climbs back above the threshold — without it, it fires every tick under 40%, which is a DPS cliff and, on a defensive vector, an infinite shield.

- [ ] **Step 4: Verify.** **Step 5: Commit** — `feat: on_low_integrity, on_flip and on_level_up triggers`

```gdscript
func the_new_modules_are_present_and_valid() -> void:
	var all := ModuleTable.all()
	var by_id := {}
	for m in all:
		by_id[m.id] = m
	for id in [&"spike", &"flood", &"snipe", &"landmine", &"cascade",
			&"bounce", &"mirror", &"throttle", &"airgap", &"checksum",
			&"on_low_integrity", &"on_flip", &"on_level_up",
			&"bitmask", &"race_condition", &"heap_spray", &"tarpit"]:
		_check("%s is in the table" % id, by_id.has(id), true)
	_check("the table is 35 modules", all.size(), 35)

	# The data sweep already validates every module; this pins the reason the
	# sweep matters for the new ones specifically.
	var errs := 0
	for m in all:
		errs += Compiler.validate(m).size()
	_check("every module validates", errs, 0)

	# A card pool that doubled would halve the odds of drawing what a build
	# needs. Roughly half the new modules ship locked so the early pool stays
	# the size it is today.
	_check("about half the new breadth is locked",
		ModuleTable.LOCKED.size() >= 10, true)
	_check("and the starting pool stays close to today's",
		ModuleTable.starting_unlocked().size() <= 26, true)
	finished["the_new_modules_are_present_and_valid"] = true
```
